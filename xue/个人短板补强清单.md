# 个人短板补强清单

基于你的简历和岗位要求整理。已过滤你简历中比较明确的能力：Vue 业务开发、Electron 桌面端、多窗口通信、uni-app、小程序、多端交付、TRTC/WebRTC、IM、ECharts、地图、后台权限、基础 Vite/Webpack/ESLint/Prettier、基础 Node/Docker/Nginx 协作。

## 核心短板

| 优先级 | 短板 | 为什么重要 | 建议 |
| --- | --- | --- | --- |
| P0 | TypeScript 深度 | 高级前端几乎默认要求 TS；你简历写了 TypeScript，但项目证据偏少 | 补泛型、工具类型、接口响应建模、组件 Props 类型、表单类型；把一个后台模块改成 strict TS |
| P0 | 浏览器性能分析 | 高级岗位常考“如何定位卡顿”，AI Native 岗也强调 Performance 面板 | 练 DevTools Performance / Memory / Network；做一个长列表或首屏优化案例，记录优化前后指标 |
| P0 | 测试能力 | 多个岗位提到自动化测试、Playwright、Jest；你简历基本没有测试产出 | 至少会写组件测试和 E2E；用 Playwright 覆盖登录、权限、列表、表单、异常态 |
| P0 | React 深度 | 很多新项目偏 React；你简历只写熟悉 React，但项目经历主要是 Vue/Electron | 补 Hooks、状态管理、React Router、性能优化、组件设计；做一个 React + TS 数据看板 |
| P1 | 工程化体系升级 | 你已有 Vite/Webpack/ESLint 基础，但高级岗看重体系化落地 | 补 pnpm、CI/CD、代码规范门禁、打包分析、发布回滚；做一套项目质量检查流程 |
| P1 | Node / BFF 深度 | 前端偏全栈和 AI 应用岗位加分；你目前更像“接口协作”而非“独立设计” | 用 Express/Koa 做 Mock/BFF、接口聚合、鉴权中间件、文件代理、SSE 流式输出 |
| P1 | AI Native 协作经验 | 高级岗位要求正在变化；AI 岗明确看重如何拆任务、审代码、验收 AI 产出 | 记录一次 AI 协作开发：需求拆解、Prompt、代码 Review、Playwright 验收、规则沉淀 |
| P1 | 技术文档表达 | 高级岗和 AI 岗都看重“把决策写清楚”；简历有规范意识但缺少文档成果 | 准备方案文档、组件文档、性能复盘、AI Review 清单；每个项目沉淀一页复盘 |
| P2 | 现代 CSS 与可访问性 | 岗位要求开始出现容器查询、`:has()`、可访问性、响应式细节 | 补 CSS 变量、Grid、容器查询、层叠上下文、键盘可用性、颜色对比度 |
| P2 | 可量化项目结果 | 简历项目很丰富，但“指标化结果”偏少，高级面试容易被追问 | 给性能、复用率、缺陷率、交付效率、包体积、首屏时间补 2-3 个可讲指标 |

## 最推荐的 4 个补强产出

| 产出 | 覆盖短板 | 做到什么程度 |
| --- | --- | --- |
| React + TS 数据看板 | React 深度、TS 深度、组件设计 | 查询筛选、图表联动、表格、详情抽屉、异步状态、类型建模 |
| 性能优化案例 | 浏览器性能分析、可量化结果 | 长列表或首屏优化，保留 Performance 截图和优化前后指标 |
| Playwright E2E 用例 | 测试能力、AI Native 验收 | 登录、权限、查询、表单提交、接口失败、空数据 |
| Node BFF + SSE Demo | Node/BFF、AI 应用岗位 | 接口聚合、Mock、鉴权、错误处理、SSE 流式返回 |

## 简历后续可补的表达

- 基于 TypeScript strict 模式完成接口响应、分页数据、表单模型和组件 Props 类型建模。
- 使用 Chrome Performance / Memory 定位长任务、重复渲染和内存泄漏，并通过虚拟滚动、代码分割、缓存策略完成优化。
- 使用 Playwright 覆盖登录、权限、列表查询、表单提交和异常态等核心流程。
- 基于 React + TypeScript 封装数据看板组件，完成筛选联动、图表渲染、详情抽屉和异步状态管理。
- 基于 Node.js 搭建 BFF/Mock 服务，完成接口聚合、鉴权中间件、文件代理和 SSE 流式响应。
- 使用 Codex/Cursor 辅助拆解前端任务，并通过人工 Review、自动化测试和性能检查验收 AI 代码。
