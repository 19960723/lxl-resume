# 前端项目作品集规划

目标：准备 2-4 个能在简历和面试中反复使用的项目，不追求“大而全”，追求能证明中高级前端能力。

## 1. 项目 A：Vue3 + TS 中后台系统

定位：主打 **Vue3 / TypeScript / 权限 / 组件化 / 工程化**。

推荐技术栈：

- Vue3 + TypeScript + Vite
- Pinia + Vue Router
- Element Plus
- Axios 或 Fetch 封装
- ECharts
- Playwright

核心功能：

- 登录页：账号密码登录、token 保存、401 失效处理。
- 首页仪表盘：核心指标卡片、趋势图、待办列表。
- 用户管理：查询、分页、增删改查、批量操作、状态切换。
- 角色权限：角色列表、菜单权限、按钮权限。
- 菜单路由：动态菜单、路由守卫、无权限页面。
- 通用组件：查询表单、高级表格、权限按钮、弹窗表单、上传组件。
- 异常处理：接口错误、空数据、加载中、网络失败、权限不足。

工程化要求：

- 使用 TypeScript strict 模式。
- 使用统一的 API 响应类型，例如 `ApiResponse<T>`、`PageResult<T>`。
- 配置 ESLint、Prettier、路径别名、多环境变量。
- 对核心流程写 Playwright E2E：登录、查询、编辑、权限拦截。

验收标准：

- 能从登录进入系统并完成至少 3 个业务模块操作。
- 权限能控制菜单、路由和按钮。
- 通用表格和表单组件能在两个以上页面复用。
- README 写清楚技术选型、目录结构、权限方案、接口封装方案。

简历表达示例：

> 基于 Vue3 + TypeScript + Vite 搭建中后台管理系统，负责登录鉴权、动态路由、RBAC 权限、接口封装和通用业务组件建设，封装查询表单、高级表格、权限按钮等组件，提升页面开发复用效率。

## 2. 项目 B：React + TS 数据看板

定位：主打 **React / TypeScript / 数据可视化 / 状态管理 / 复杂交互**。

推荐技术栈：

- React + TypeScript + Vite
- React Router
- Zustand 或 Redux Toolkit
- Ant Design
- ECharts
- TanStack Query 可选

核心功能：

- 数据概览：指标卡、趋势折线图、柱状图、环形图。
- 多条件筛选：时间范围、业务线、状态、关键词。
- 明细表格：排序、筛选、分页、列配置、导出。
- 详情抽屉：点击图表或表格行打开详情。
- 异步状态：loading、error、empty、retry。
- 主题切换：明暗主题或品牌色切换。

工程化要求：

- 所有接口响应和图表数据建 TS 类型。
- 对图表组件做 Props 约束，避免页面直接堆配置。
- 使用 memo、useMemo、useCallback 处理高频渲染点。
- 对筛选条件和 URL query 做同步，方便分享和刷新恢复。

验收标准：

- 至少 4 类图表，且能由筛选条件联动。
- 表格、筛选、详情抽屉形成完整业务闭环。
- 能解释 React 组件拆分、状态管理和性能优化思路。

简历表达示例：

> 基于 React + TypeScript 实现数据分析看板，封装指标卡、趋势图、明细表格和详情抽屉等组件，完成筛选条件联动、异步状态管理和图表性能优化，提升复杂数据场景下的交互体验。

## 3. 项目 C：前端性能优化案例

定位：主打 **性能诊断 / 长列表 / 首屏 / 可量化结果**。

推荐场景：

- 一个 5000-10000 条数据的列表页面。
- 一个首屏资源较多的后台首页。
- 一个图表数量多、交互频繁的数据看板。

优化前记录：

- 首屏加载时间。
- JS 包体积。
- Long Task 数量和最长耗时。
- 列表滚动 FPS 或卡顿体感。
- Network 请求数量。

可用优化手段：

- 路由级代码分割。
- 组件懒加载。
- 图片懒加载和压缩。
- 长列表虚拟滚动。
- 大数据计算移出渲染路径。
- 防抖、节流、请求合并。
- 缓存静态配置和字典数据。
- 减少无意义响应式深层代理。

验收标准：

- 至少保留一组优化前后截图。
- 至少记录 3 个指标变化。
- 能讲清楚瓶颈定位过程，而不是只讲最终方案。

简历表达示例：

> 针对列表滚动卡顿和首屏加载慢问题，使用 Chrome Performance 定位长任务与重复渲染，通过虚拟滚动、代码分割、懒加载和缓存策略降低渲染压力，并记录优化前后性能指标。

## 4. 项目 D：AI Native 前端协作案例

定位：主打 **AI agent 协作 / 自动化验收 / 规则沉淀**。

推荐做法：

- 选择项目 A 或 B 的一个模块，例如“用户管理”。
- 先写需求说明和接口契约。
- 用 Codex/Cursor/Claude Code 拆任务生成初版代码。
- 自己做代码 Review，记录 AI 错误。
- 用 Playwright 写验收用例。
- 把反复出现的问题沉淀成规则文档。

需要记录的内容：

- 任务如何拆分。
- 哪些交给 AI，哪些自己做。
- AI 生成代码出现了哪些问题。
- 你如何判断、修复和验收。
- 最终沉淀了哪些规范。

验收标准：

- 有一份 `AI协作开发记录.md`。
- 有一份 `AI代码Review清单.md`。
- 有 5 条以上 Playwright 用例。
- 有一段不超过 200 字的投递回答。

简历表达示例：

> 在前端模块开发中引入 AI 协作流程，将需求拆解为组件、接口、测试和文档任务，使用 Codex/Cursor 辅助生成初版代码，并通过人工 Review、Playwright E2E 和性能检查完成验收，沉淀 AI 代码质量规则。

## 5. 面试讲项目的结构

每个项目都按这个顺序准备：

1. 背景：这个项目解决什么业务问题。
2. 职责：你负责哪些模块，边界是什么。
3. 难点：权限、性能、组件复用、复杂交互、质量保障中选 2-3 个。
4. 方案：为什么这样设计，有没有备选方案。
5. 结果：最好有指标，没有指标也要有复用、稳定性、效率方面的结果。
6. 复盘：如果重做，会优化什么。

## 6. 作品集优先级

- 第一优先级：Vue3 + TS 中后台项目。
- 第二优先级：性能优化案例。
- 第三优先级：AI Native 协作案例。
- 第四优先级：React + TS 数据看板。

如果时间有限，先把 Vue3 项目和性能案例做扎实，比同时开很多半成品更有价值。
